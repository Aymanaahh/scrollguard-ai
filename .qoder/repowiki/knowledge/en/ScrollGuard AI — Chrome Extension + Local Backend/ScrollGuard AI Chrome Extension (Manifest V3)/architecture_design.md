Flat Manifest V3 package declaring three execution contexts registered in `manifest.json`: a background service worker (`background.js`) under `background.service_worker` acting as the privileged proxy to the FastAPI backend, a content script (`content.js`) injected at `document_idle` into `<all_urls>` to scan DOM anchors, and a popup UI (`popup.html` + `popup.js`) bound via `action.default_popup`. The content script runs a three-phase pipeline — (1) scan the main page URL itself, (2) initial scan of all existing `<a>` tags, (3) a `MutationObserver` on `document.body` with a 300 ms debounce that re-scans only newly inserted nodes. Links are filtered through allowlist (`TRUSTED_DOMAINS`), auth-path keywords (`AUTH_PATH_KEYWORDS`), scheme/protocol checks, same-origin rejection, and SPA stubs before being batched to the background via `chrome.runtime.sendMessage({ action: 'scanPageLinks', links })`. The background resolves the backend URL from `chrome.storage.local` key `sg_backendUrl` (defaulting to `http://127.0.0.1:8000/scan_links`), POSTs the link array, and returns results back to the caller; it returns `true` from the message listener to keep the channel open for async responses. Results are applied in the content script via inline DOM mutation (`element.style.outline`, `backgroundColor`, badge insertion) and in the popup which independently queries the active tab URL via `chrome.tabs.query` and reuses the same `scanPageLinks` message path to render per-link status cards. Cross-context state (scan counters) is shared through `chrome.storage.local` keys `sg_linksScanned` / `sg_linksFlagged`, with live push updates via a second message type `updateStats` sent from content to any open popup. A session-scoped flagged-links history (persisted under `sg_flaggedLinks` and cleared on `onStartup`) is exposed to the popup via a `getFlaggedLinks` message.
